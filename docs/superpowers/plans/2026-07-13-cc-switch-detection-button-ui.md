# CC Switch Detection and Primary Button UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 Windows CC Switch 安装检测路径，并提升“开始安装”按钮的可点击感与状态反馈。

**Architecture:** 保持现有 Tauri/Rust 适配器和原生 TypeScript 渲染结构。通过修正版本清单中的实际 Windows 可执行文件名解决当前误报，并通过已有 `.primary-button` 样式完成主操作视觉优化，不新增依赖。

**Tech Stack:** Rust、Tauri 2、Serde、TypeScript、Vite、Vitest、JSDOM、原生 CSS。

## Global Constraints

- 不保存账号、密码或 Token。
- 不改变现有安装流程和平台适配器接口。
- 主按钮必须保留键盘焦点样式和明确的禁用态。
- Windows CC Switch 检测必须兼容实际的 `cc-switch.exe` 文件名。

---

### Task 1: 修复 CC Switch Windows 检测路径

**Files:**
- Modify: `assets/manifest.json`
- Modify: `src-tauri/src/adapters/mod.rs`

**Interfaces:**
- Consumes: `AppRelease.windows_executable` and `DesktopAppAdapter::candidate_paths()`.
- Produces: candidates including `cc-switch.exe` under the current user's Programs directory.

- [ ] **Step 1: 将清单中的可执行文件名改为实际文件名**

把 `assets/manifest.json` 中 Windows x64 的 CC Switch 路径从：

```json
"windows_executable": "Programs/CC Switch/CC Switch.exe"
```

改为：

```json
"windows_executable": "Programs/CC Switch/cc-switch.exe"
```

- [ ] **Step 2: 扩展 Windows 候选路径测试**

在 `src-tauri/src/adapters/mod.rs` 测试模块中增加断言，验证候选路径包含 `cc-switch.exe`，并覆盖 `LOCALAPPDATA/Programs/CC Switch` 形式的路径。

- [ ] **Step 3: 运行适配器测试**

运行：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml adapters
```

预期：适配器测试全部通过。

### Task 2: 优化“开始安装”按钮状态

**Files:**
- Modify: `src/styles.css`
- Test: `src/ui/render.test.ts`

**Interfaces:**
- Consumes: Existing `.primary-button` markup and `disabled` attribute generated by `src/ui/render.ts`.
- Produces: Distinct enabled, hover, pressed, focus-visible and disabled states.

- [ ] **Step 1: 增加按钮渲染测试**

在 `src/ui/render.test.ts` 增加一个可安装状态，断言安装按钮存在且未禁用；保留现有不可安装测试，断言按钮继续禁用。

- [ ] **Step 2: 调整主按钮样式**

将 `.primary-button` 启用背景从灰色改为高对比蓝色，并增加 `transition`、`:hover`、`:active`、`:focus-visible`；将灰色只保留给 `.primary-button:disabled`，同时设置 `opacity: 1` 以避免可点击按钮看起来像禁用状态。

- [ ] **Step 3: 运行前端测试和构建**

运行：

```powershell
npm run test
npm run build
```

预期：所有测试通过，Vite 构建成功。
