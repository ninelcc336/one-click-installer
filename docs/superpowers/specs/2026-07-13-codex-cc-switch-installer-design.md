# Codex 与 CC Switch 一键安装器设计

## 1. 目标与范围

为 Windows 10/11 和 macOS 普通用户提供一个简单、可靠的安装向导，自动完成：

1. 检测操作系统、CPU 架构、磁盘空间、网络和安装权限。
2. 安装 Codex 桌面应用和 CC Switch。
3. 创建快捷方式或应用入口。
4. 验证安装结果并启动应用。
5. 在下载失败、权限取消或中途退出后提供重试和恢复能力。

安装器不负责账号登录、Token 管理、复杂配置迁移或后台静默升级。

## 2. 用户流程

```text
欢迎页
  -> 系统检测
  -> 安装前确认
  -> 安装 Codex
  -> 安装 CC Switch
  -> 创建快捷方式
  -> 验证并启动
  -> 完成页
```

界面采用单窗口、单主按钮、逐步推进的向导模式。主要页面如下：

### 欢迎页

展示“一键安装 Codex 和 CC Switch”，提供“开始安装”和“退出”。

### 系统检测页

检测系统版本、CPU 架构、磁盘空间、网络、权限，以及两个应用是否已经安装。状态只使用“可以安装”“需要授权”“无法继续”。

### 安装确认页

列出将要安装的两个应用和快捷方式。默认不展示复杂技术选项。

### 安装进度页

分别显示 Codex 和 CC Switch 的下载、校验、安装状态。失败时提供“重试”“跳过此项”“退出安装”。“跳过”必须说明后果。

### 完成页

提供启动 Codex、启动 CC Switch 和完成按钮，并提醒用户首次使用时在应用内登录。安装器不接触账号密码。

### 已安装与失败页面

已安装应用默认保留，不覆盖较新版本。失败页面显示软件名称、失败步骤、可理解的原因、下一步建议、复制诊断信息和打开日志目录。

## 3. 系统架构

```text
安装器界面
  |
流程控制器
  |-- 环境检测器
  |-- 下载与校验模块
  |-- 权限与安装执行器
  |-- Codex 安装适配器
  |-- CC Switch 安装适配器
  |-- 安装结果验证器
  `-- 日志与故障恢复模块
```

界面不直接写死某个软件的安装细节。每个应用通过独立适配器提供以下能力：

- 检测安装状态和当前版本。
- 选择对应系统与架构的安装包。
- 执行安装。
- 验证安装结果。
- 将底层错误转换为普通用户可理解的提示。

后续增加第三个工具时，只需新增适配器和版本清单，不重写流程控制器。

## 4. 下载与版本管理

安装器使用版本清单管理安装包，不把 URL 和版本号散落在代码中。清单按应用、系统和 CPU 架构组织，并包含版本号、下载地址、文件大小和 SHA-256。

下载策略：

- 自动选择 Windows 或 macOS，以及 Intel、Apple Silicon 等架构。
- 显示文件大小和下载进度。
- 支持断点续传和最多三次重试。
- 下载完成后校验 SHA-256，校验失败立即删除文件并禁止安装。
- 优先使用官方安装包地址；必要时配置自有镜像。
- 内置一份备用版本清单，远程清单不可用时仍能继续安装已知版本。

版本规则：

- 已安装版本满足要求时跳过。
- 已安装版本较旧时提示升级。
- 已安装版本较新时保留现有版本，不降级。
- 用户主动选择重装时，不删除用户数据。

## 5. 权限与平台行为

Windows：需要管理员权限时触发系统 UAC，并说明授权用途。用户取消授权时显示“你取消了授权，可稍后重试”，不将其误报为安装器故障。

macOS：优先安装到当前用户的 Applications 目录；只有必须写入系统目录时才请求管理员密码。根据分发方式处理应用签名、公证和系统安全提示。

临时下载文件放入临时目录，成功后清理。失败或中断时保留可恢复所需的信息，并清理无效或校验失败的文件。

## 6. 状态、恢复与验证

安装器记录明确的状态序列，例如：

```text
检测完成
Codex 下载完成
Codex 校验完成
Codex 安装失败
CC Switch 未开始
```

恢复行为：

- 下载失败：从断点继续或重新下载。
- 校验失败：删除文件后重新下载。
- 安装程序返回失败：展示具体建议并保留诊断日志。
- 安装成功但启动验证失败：提示用户手动打开应用，不直接判定安装失败。
- 用户中途退出：下次打开时提供继续或重新开始。

安装验证至少包括应用文件存在、版本可读取、启动行为正常，以及快捷方式或应用入口创建成功。

## 7. 安全与隐私

- 所有安装包记录 SHA-256。
- Windows 安装器尽量进行代码签名。
- macOS 分发包尽量进行签名和公证。
- 不保存账号、密码、Token 或聊天内容。
- 日志自动隐藏 Token、环境变量敏感值和路径中的用户名。
- 不默认收集远程诊断数据；用户主动导出诊断信息后再分享。

## 8. 技术选型

推荐使用 Tauri 2 构建跨平台安装向导，界面采用 HTML/CSS/TypeScript，系统安装和权限能力通过 Rust 封装。Windows 使用 NSIS 安装包，macOS 使用 DMG，必要时补充 PKG。

如果开发团队不熟悉 Rust，可改用 Electron，以降低开发门槛，但需要接受更大的安装包体积。

建议的模块划分：

```text
installer-ui       页面和交互
install-core       流程状态机、重试、恢复、取消
platform           Windows/macOS 系统能力
adapters           Codex 与 CC Switch 安装适配器
download           下载、断点续传、校验、缓存清理
verify             安装结果、版本、启动验证
diagnostics        日志、脱敏、诊断信息导出
```

## 9. 第一版验收标准

在 Windows 10/11、macOS Intel 和 macOS Apple Silicon 上验证：

- 全新环境可以安装两个应用。
- 已安装应用不会被无提示覆盖。
- 无管理员权限或用户取消授权时有清晰提示。
- 网络中断后可以重试或继续下载。
- 包校验失败时不会执行安装。
- 安装器中途关闭后可以恢复或重新开始。
- 安装完成后两个应用都能被找到并启动。
- 失败页面能说明发生了什么以及下一步怎么做。
- 日志中不出现账号、密码和 Token。

## 10. 第一版明确不做

- 自动登录账号。
- 自动读取、保存或修改 Token。
- 复杂配置迁移。
- 后台静默升级。
- 内置代理或 VPN。
- 软件商店和远程用户数据采集。
- 非必要的多语言支持。
